# SCORM Add-on — Design System Alignment Tracker

Scope: **theme only** (colors, dark mode, component skin). No layout/UX restructuring, no controller/model/route changes, no removed fields or actions.

Source of truth: `assets/design-system/reference/geeseprojdesignsystem.html` + `--gp-*` tokens in `assets/design-system/gp-tokens.css`. Helpers: `gp_ds_button`, `gp_ds_badge`, `gp_ds_alert` (`application/helpers/design_system_helper.php`).

Baseline findings that shape every row below:
- `course_edit.php` (admin + user) is **already** on the DS shell (`gp_ds_page_title`, `gp_ds_button`, `gp_ds_alert`), so no work needed there beyond what's noted.
- `.btn-primary/.btn-success/.btn-info/.btn-danger` are already themed **globally** under `.gp-ds` (`gp-components-core.css`) — SCORM's buttons inherit this for free already in both themes.
- `.alert-success` / `.alert-warning` / `.alert-info` / `.alert-danger` are already themed when the markup sits inside `#curriculum` or a `.gp-addon-tab` wrapper (`gp-admin-courses.css` Phase 8 rules). `scorm_curriculum.php` sits directly inside `#curriculum`, so those 4 tones already work — but `.alert-light` is **not** one of the covered tones, and the alert's `<h5>` heading isn't covered because the CSS targets `.alert-heading`, not a bare `<h5>`.
- `.custom-file` / `.badge-light` / `.btn-success` (modal variant) are only themed when the markup is wrapped in `.gp-courses-modal` (`gp-admin-courses.css` ~L1321+), the same convention `lesson_add.php`, `quiz_add.php`, etc. already use. `scorm_course_uploading_form.php` (shown via `showAjaxModal`) does **not** have this wrapper today.
- `.course-provider-logo` / `.course-provider-logo-checked` (`assets/backend/css/main.css:338-366`) hardcode `rgb(0, 208, 79)` and `#bcbcbc` with **no dark-mode variant at all** — this is the most visible bug (a bright, unthemed green/gray box in dark mode).
- Admin and instructor (`backend/user/**`) SCORM partials are near-identical (diff confirmed), so each fix below applies to both copies.

## Explicitly out of scope
- Controllers/models: `application/controllers/addons/Scorm.php`, `application/models/addons/scorm_model.php` — untouched.
- Layout/structure of `course_add.php` / `course_edit.php` / `course_add_shortcut.php` — the "SCORM" `<option>` in the course-type `<select>` already inherits the site-wide themed Select2 skin; no changes needed there.
- The visual content **inside** the SCORM iframe (the uploaded iSpring/Articulate/Captivate package) — that's user-uploaded third-party HTML, not part of this app's design system.
- `scorm_scripts.php`'s `NotificationApp.send(..., "rgba(0,0,0,0.2)", "error")` toast call — this is the same shared toast pattern used by every other addon; not a SCORM-specific issue.
